API Reference

AIRA API Documentation

The AIRA API is organized around REST. Our API has predictable resource-oriented URLs, accepts JSON-encoded request bodies, returns JSON-encoded responses, and uses standard HTTP response codes, authentication, and verbs.

You can use the AIRA API in test mode, which doesn't affect your live data. The API key you use to authenticate the request determines whether the request is live mode or test mode.

Authentication

The AIRA API uses API keys to authenticate requests. Provide your API key as a Bearer token:

Authorization: Bearer YOUR_API_KEY

All API requests must be made over HTTPS. Calls made over plain HTTP will fail.

Base URL

https://api.aira.ai/v1

Errors

AIRA uses conventional HTTP response codes to indicate success or failure.

200Everything worked as expected.
400Bad Request – missing or invalid parameter.
401Unauthorized – no valid API key provided.
404Not Found – the requested resource doesn't exist.
500Server Error – something went wrong on AIRA's end.

Quick Start

  1. Obtain your API key – Contact our sales team to get access and receive your credentials.
  2. Make your first request
    curl https://api.aira.ai/v1/status \ -H "Authorization: Bearer YOUR_API_KEY"
  3. Create an account holder – Start by creating an account holder to issue cards to.
  4. Issue a card – Create virtual or physical cards for your account holders.
  5. Test with simulations – Use the simulation endpoints to test authorization flows without real transactions.

Account Holders

Account holders represent the individuals or businesses that hold cards on your program. Create an account holder before issuing any cards.

Endpoints

POST/account-holders
Create a new account holder
GET/account-holders/{id}
Retrieve an account holder
PUT/account-holders/{id}
Update an account holder
GET/account-holders
List all account holders

Create an Account Holder

Creates a new individual or business account holder and runs automated KYC checks.

Parameters

ParameterTypeDescription
typerequiredstringEither individual or business.
first_namerequiredstringFirst name (individual only).
last_namerequiredstringLast name (individual only).
emailrequiredstringEmail address of the account holder.
date_of_birthstringISO 8601 date (individual only). Required for KYC.
addressobjectBilling address object with line1, city, state, postal_code, country.
metadataobjectSet of key-value pairs for storing additional information.

Example request

curl https://api.aira.ai/v1/account-holders \ -H "Authorization: Bearer YOUR_API_KEY" \ -H "Content-Type: application/json" \ -d '{ "type": "individual", "first_name": "Jane", "last_name": "Smith", "email": "jane@example.com", "date_of_birth": "1990-05-15", "address": { "line1": "123 Main St", "city": "San Francisco", "state": "CA", "postal_code": "94105", "country": "US" } }'

Cards

Issue virtual or physical cards to your account holders. Cards can be single-use or reloadable, and can be assigned spending controls and limits.

Endpoints

POST/cards
Issue a new card
GET/cards/{id}
Retrieve a card
PUT/cards/{id}
Update card spending controls
PUT/cards/{id}/status
Activate, suspend, or cancel a card
GET/cards
List all cards

Issue a Card

Issues a virtual or physical card to an existing account holder.

Parameters

ParameterTypeDescription
account_holder_idrequiredstringID of the account holder to issue the card to.
typerequiredstringvirtual or physical.
programrequiredstringprepaid, single_use, or small_business.
spending_controlsobjectOptional spending limits and merchant category restrictions.
metadataobjectSet of key-value pairs for storing additional information.

Example request

curl https://api.aira.ai/v1/cards \ -H "Authorization: Bearer YOUR_API_KEY" \ -H "Content-Type: application/json" \ -d '{ "account_holder_id": "ah_1A2B3C4D", "type": "virtual", "program": "prepaid", "spending_controls": { "spending_limits": [ { "amount": 50000, "interval": "monthly" } ] } }'

Transactions

Transactions represent card authorizations, captures, and declines. Each transaction is linked to a card and an account holder.

Endpoints

GET/transactions/{id}
Retrieve a transaction
GET/transactions
List all transactions

List Transactions

Returns a paginated list of transactions, optionally filtered by card or date range.

Query parameters

ParameterTypeDescription
card_idstringFilter by card ID.
account_holder_idstringFilter by account holder ID.
statusstringpending, settled, or declined.
created_afterstringISO 8601 timestamp — return transactions created after this time.
created_beforestringISO 8601 timestamp — return transactions created before this time.
limitintegerNumber of results per page (default 25, max 100).
cursorstringPagination cursor from a previous response.

Example request

curl "https://api.aira.ai/v1/transactions?card_id=card_XYZ&limit=10" \ -H "Authorization: Bearer YOUR_API_KEY"

Credits

Credits add funds to a card's available balance. Use credits to load prepaid cards, issue refunds, or apply promotional balances.

Endpoints

POST/credits
Create a credit
GET/credits/{id}
Retrieve a credit
GET/credits

Create a Credit

Adds funds to a card's available balance immediately.

Parameters

ParameterTypeDescription
card_idrequiredstringID of the card to credit.
amountrequiredintegerAmount in the smallest currency unit (e.g., cents for USD).
currencyrequiredstringThree-letter ISO 4217 currency code (e.g., USD).
descriptionstringOptional memo shown on the cardholder's statement.
metadataobjectSet of key-value pairs for storing additional information.

Example request

curl https://api.aira.ai/v1/credits \ -H "Authorization: Bearer YOUR_API_KEY" \ -H "Content-Type: application/json" \ -d '{ "card_id": "card_XYZ", "amount": 10000, "currency": "USD", "description": "Initial load" }'

Statements

Statements provide a periodic summary of card activity. Statements are generated automatically at the end of each billing cycle.

Endpoints

GET/statements/{id}
Retrieve a statement
GET/statements/{id}/transactions
List transactions on a statement
GET/statements
List all statements

The Statement Object

FieldTypeDescription
idstringUnique identifier for the statement.
card_idstringThe card this statement belongs to.
period_startstringISO 8601 start date of the statement period.
period_endstringISO 8601 end date of the statement period.
opening_balanceintegerBalance at the start of the period (cents).
closing_balanceintegerBalance at the end of the period (cents).
total_creditsintegerTotal credits applied during the period (cents).
total_debitsintegerTotal debits applied during the period (cents).

Simulations

Simulation endpoints let you test your integration in test mode without real network activity. Trigger authorizations, reversals, and other card events programmatically.

Endpoints

POST/simulations/authorizations
Simulate a card authorization
POST/simulations/authorizations/{id}/capture
Simulate capturing an authorization
POST/simulations/authorizations/{id}/void
Simulate voiding an authorization
POST/simulations/payments/{id}/settle
Simulate settling a pending payment

Simulate an Authorization

Creates a test authorization against a card. Only available in test mode.

Parameters

ParameterTypeDescription
card_idrequiredstringID of the card to authorize against.
amountrequiredintegerAuthorization amount in the smallest currency unit.
merchant_namestringSimulated merchant name.
merchant_category_codestringFour-digit MCC for the simulated merchant.

Example request

curl https://api.aira.ai/v1/simulations/authorizations \ -H "Authorization: Bearer YOUR_TEST_API_KEY" \ -H "Content-Type: application/json" \ -d '{ "card_id": "card_XYZ", "amount": 2500, "merchant_name": "Test Merchant", "merchant_category_code": "5411" }'
